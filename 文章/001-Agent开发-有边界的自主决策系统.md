# 001｜Agent 开发：有边界的自主决策系统

- 主题标签：Agent、ReAct、Plan-and-Execute、多 Agent、工具调用、异常处理、安全护栏

## 一句话总结

Agent 开发不仅是接入工具，更是围绕目标、约束、异常处理和退出机制，构建可自主决策、可持续迭代的工程系统。

## 关键信息

1. **先理解任务，再选择架构。** ReAct、Plan-and-Execute、多 Agent 协作是可选方案。设计前应明确用户意图、任务规模、信息是否充分，以及执行环境、超时等约束。
2. **把不确定性纳入系统设计。** 幻觉、循环执行、工具失败都需要处理。不能仅靠重试或兜底话术，应预先设置重试上限、超时、熔断、替代方案与挂起机制。
3. **Agent 必须拥有停下来的能力。** 工具失败时不能编造结果；证据不足时应说明不确定性；达到执行边界时应停止、降级或转人工。
4. **核心是“有边界的自主性”。** 明确目标、约束、工具权限和退出条件，让 Agent 在边界内选择行动，同时保留人工介入入口。

## 原文

面试过不少 AI 开发候选人，大部分人对 Agent 的理解都停留在标准答案——
会背概念、懂 LangGraph，也能聊 ReAct 和 Function Calling，知识点都没问题，但总缺落地思考。
今天面试的这个女生，三个问题聊下来，我一直在点头。
问到 Agent 开发到底在做什么，很多人只会说给大模型加工具调用，用来查数据、调接口。
但她的思路更成体系：Agent 开发，本质是搭建一套可迭代的决策系统。
什么时候用 ReAct，什么时候用 Plan-and-Execute，多 Agent 怎么通信，这些架构选择，才决定系统上限。
拿代码辅助 Agent 举例，很多人简单对接工具就准备上线。她却会考虑：用户是写新代码还是修 bug？代码规模多大？缺信息要不要主动追问？执行环境安不安全，超时怎么处理？
这些不只是模型问题，更是工程架构要兜底的事。
接着聊 Agent 出错该怎么处理。
大部分人的回答就是重试，加兜底话术。
她看得很透彻：Agent 最大难点是不确定性。模型幻觉、死循环、工具调用接连失败都是常态。调用失败不能让模型瞎编结果，而是切换方案，重试达到上限就主动挂起。
上线前就要定好重试次数、超时、熔断规则，拿不准的结果，直接如实告知用户，不能硬给答案。Agent 要拥有停下来的能力。
最后问她，做 Agent 最难的地方在哪。
她回答：设计有边界的自主性。
交给 Agent 任务，就像安排工作给新人。不用卡死每一步操作，但要明确目标、约束条件、退出机制。给它自主空间，同时预留降级和人工介入的入口。
很多人为了防止 Agent 跑偏，疯狂写死 if-else 逻辑，最后做出来只是套着 Agent 外壳的固定工作流。真正的 Agent 开发，不是管控每一步动作，而是定义好目标、约束、工具与安全护栏，交给它自主完成任务。
这就是差距。
不少人还在琢磨怎么让 Agent 乖乖执行指令，而她思考的，是如何搭建一套既能自主决策，又可以持续迭代的工程系统。
